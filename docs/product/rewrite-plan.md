# SmartImage Go 重写：功能盘点与产品设计

> 状态：已确认，P1、P2、P3、P4、P5、P6 已实现。
> 日期：2026-11-05

## 一、旧版入口

| 入口 | 触发方式 | 实际行为 |
| --- | --- | --- |
| `run.bat` | 拖拽图片/文件夹到 bat，或「发送到 → 转成 WebP」 | 静默转 WebP，控制台进度，结束 5 秒后关窗，失败弹系统对话框 |
| `run_interactive.bat` | 拖拽到 bat，或「发送到 → 更多图片转换处理」 | 终端数字键菜单，进入对应参数向导，可返回主菜单 |
| `start-ui.bat` | 双击，或「发送到 → 界面切图」 | 启动本地 Express 服务（127.0.0.1:3000）并打开浏览器；每个图片参数单独起一个进程和页面 |
| CLI | `node lib/convert.js <路径...> [--format X] [--interactive] [--ai-model medium|small]` | 与上面两条 bat 相同的引擎，退出码 0/1/2 |
| 安装脚本 | `scripts/install.ps1` | 在 Windows「发送到」目录创建 3 个快捷方式 |

### 2.2 切图编辑器的能力

旧版 Web UI 只服务于「自定义切分线」这一件事，但做到了很细：

- 加载：路径输入、文件对话框、拖拽（注意：浏览器拖拽拿不到绝对路径，旧版这里实际会失败）
- 视图：缩放（按钮/百分比）、平移（空格临时抓手或平移模式）、自适应窗口
- 切分线：点击添加竖线/横线、Alt+点击添加另一方向、颜色分组（X/Y 各 4 色）、吸附
- 辅助：4 倍放大镜、行列等分（1–50）、切分线严格递增校验
- 居中：智能居中开关、容忍度滑块、补白色、导出格式、参与居中的边
- 提交：写入原图同级目录，返回成功/部分失败/失败
- 生命周期：服务闲置 5 分钟自动退出、任务写盘期间禁止退出、心跳

### 2.3 横切能力

- 递归发现：目录递归、深度上限 10、符号链接防死循环、不可访问路径告警、去重、截断计数
- 批处理：并发窗口 5、单文件错误隔离、进度动画、成功/跳过/失败汇总、错误日志按日写 `log/error_YYYY-MM-DD.log`
- 落盘安全：`O_EXCL` 独占占位、同名 `(1)` 递增、失败清理幽灵文件、零产出回滚目录
- 方向：所有几何运算前按 EXIF 摆正
- 编码：WebP q80/effort6、PNG q80/effort8、AVIF q75/effort7、JPEG q85 mozjpeg 4:4:4、AI 输出 PNG 关闭调色板
- 退出码：0 成功、1 失败、2 用户取消
- Web 服务：仅回环、路径沙箱、单任务并发闸门、空闲退出

## 三、旧版的产品问题

1. **入口分散**：三个 bat 各管一类，用户要先判断“我该点哪个”，右键菜单也只有 3 个固定项。
2. **终端菜单不可发现**：数字键向导无鼠标、无预览、无搜索；参数填错只能整轮重来。
3. **切图与批处理割裂**：切图必须开浏览器，Web UI 不能做其他操作；批处理又不能可视化调线。
4. **没有记忆**：每次都要重选格式、重填阈值、重选方向。
5. **结果不可见**：只有控制台文字，不显示缩略图、体积变化、输出路径；用户得自己去找文件。
6. **错误不可行动**：失败原因混在日志里，没有失败列表、重试、定位。
7. **不能取消/暂停**：长任务只能等结束。
8. **输出规则不统一**：有的加 `_optimized`，有的加 `_resized`，有的进子目录，有的新建目录；用户无法预测。
9. **拖拽路径缺陷**：Web UI 拖拽只能拿到文件名，实际无法切图。
10. **安装/更新缺失**：依赖 Node、首次 npm install、无版本更新与卸载。

## 四、Go 版产品定位

**一个本地图片批处理工作台**，不是三个脚本的 Go 翻译：

- **发起**：右键「发送到」、拖拽到 exe/窗口、打开主窗口。
- **配置**：在主窗口完成，参数与预览即时可见。
- **执行**：统一任务队列，可取消、可重试、可查看每个文件。
- **收尾**：结果卡片、体积变化、打开输出目录、失败原因。
- **记忆**：记住上次操作与参数，支持预设。

### 4.1 入口设计

Windows「发送到」是快捷方式文件夹，**不支持级联子菜单**。可选三条路：

| 方案 | 做法 | 成本 | 体验 |
| --- | --- | --- | --- |
| A. 扁平快捷项 | 发送到里放 8–10 个功能快捷方式 | 低，无需管理员 | 菜单长，但一键直达 |
| B. 单一入口 + 工作台 | 只放「SmartImage…」，打开后带入选中的文件 | 低 | 好，但多一步 |
| C. Shell 扩展级联菜单 | 注册 COM/注册表，右键直接出级联菜单 | 高，需签名/管理员，Win11 新旧菜单差异大 | 最好 |

**已确认 B + 少量 A**：「转成 WebP」保留一键；「SmartImage 图片工具」带文件打开工作台，在工作台里选所有功能。这样不牺牲高频操作，也不需要 shell 扩展。发送到快捷方式由 `scripts/install-sendto.ps1` 创建，`-Uninstall` 移除。

### 4.2 主窗口信息架构

```text
┌ 侧栏 ─────────┬ 文件队列 / 预览 ──────────────┬ 参数面板 ─────┐
│ 快速转换       │ [缩略图] 文件名  类型  尺寸    │ 当前操作的参数 │
│ 尺寸调整       │ [缩略图] 文件名  类型  尺寸    │ 预设 / 上次使用│
│ 边缘处理       │ ...                            │               │
│ 构图           │                                │               │
│ 切图           │                                │               │
│ AI 抠图        │                                │               │
│ 设置           │                                │               │
├───────────────┴────────────────────────────────┴───────────────┤
│ 输出策略：同目录 / 子目录 / 指定目录    [取消]  [开始处理]        │
└───────────────────────────────────────────────────────────────┘
```

- 一个操作页只显示该操作的参数，不再用终端式多步向导。
- 拖入文件后若最近用过某操作，显示「再次执行：上次的 WebP 转换」+「选择其他操作」。
- 处理中：任务中心显示每个文件的缩略图、进度、原体积→新体积、节省比例、状态。
- 失败：失败文件单独列出，带原因和「重试」；不阻断其他文件。
- 完成后：一键「打开输出文件夹」。

### 4.3 切图页

原生 Canvas 编辑器，功能对齐旧 Web UI 并补齐：

- 缩放/平移/自适应、空格临时抓手
- 点击加线、Alt+点击加另一方向、颜色分组、吸附、放大镜
- 行列等分、切分线递增校验、最多 500 片实时计数
- 智能居中：容忍度、补白色、导出格式、参与边
- 实时切片预览（悬停高亮当前瓦片）
- 导出前显示：切片数、预计总大小、输出目录
- 拖拽文件直接拿到绝对路径（修复旧版缺陷）

### 4.4 统一输出规则（P1–P4 已实现）

- **位置**三选一，全局记忆：
  - 原图所在文件夹（默认）
  - 原图旁的子文件夹，名称可改；转换默认 `converted`，其他操作各有默认名
  - 指定文件夹
- **命名**：
  - 换格式：保留原文件名，只换扩展名（`photo.png` → `photo.webp`）
  - 同格式再编码：加 `_optimized`（`photo.png` → `photo_optimized.png`）
  - 尺寸/构图类变换：加操作后缀，如 `_resized`
- **冲突**：文件用 `photo(1).webp` 递增；切图等新建目录用 `photo(1)/`
- **跳过**：源已是目标 WebP/AVIF 时跳过，不产生重复编码
- **落盘**：先 `O_EXCL` 占位，编码失败或取消时删除占位，不留 0 字节文件
- **方向**：所有操作先按 EXIF 摆正，再计算尺寸与坐标

## 五、功能与交互优化决策

| 项 | 旧版 | Go 版建议 | 理由 |
| --- | --- | --- | --- |
| 入口 | 3 个 bat + 3 个发送到 | 1 个应用 + 1 个主入口 + 1 个一键 WebP | 降低选择成本 |
| 参数输入 | 终端数字键向导 | 原生表单 + 预设 | 可发现、可修改、可回退 |
| 去边/裁剪 | 主菜单两个分支 | 「边缘处理」页内两个模式 | 同一心智模型 |
| 居中/扩边 | 两个独立菜单项 | 「构图」组内两页 | 都依赖主体 bbox |
| 输出规则 | 后缀/子目录/新目录混用 | 统一默认 + 可选兼容旧规则 | 可预测 |
| 结果反馈 | 控制台文字 | 卡片 + 缩略图 + 体积变化 + 打开目录 | 可验证 |
| 失败处理 | 日志 | 失败列表 + 重试 + 原因 | 可行动 |
| 长任务 | 不能取消 | 取消 + 已取消文件保留 | 可控制 |
| 重复配置 | 每次重填 | 记住上次 + 预设 | 提效 |
| 切图入口 | 浏览器 | 原生页 + 拖拽绝对路径 | 修复缺陷、统一体验 |
| AI 抠图 | 依赖 Node/ONNX | 保留 medium/small；先定运行方式 | 能力不降级 |

**不删除任何旧功能**，但也不 1:1 复制终端向导。

## 六、实施顺序（按用户可见结果切）

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| P1 工作台闭环 | 主窗口骨架、文件队列、快速转换（4 格式）、结果卡片、打开目录、设置记忆、取消、右键/拖拽入口 | 拖一批图 → 一次点击 → 看到每份结果与体积变化 → 打开目录 |
| P2 尺寸与边缘 | 缩放、去边、裁剪三个页 | 参数预览 + 批量产物规则一致 |
| P3 构图 | 智能居中、画布扩边 | 同图与旧版结果尺寸/边距一致 |
| P4 切图 | 原生 Canvas 编辑器 + 切片管线 | 与旧 Web UI 操作等价，切图结果一致 |
| P5 AI 抠图 | 抠图页 + 运行方式落地 | medium/small 都能产出透明图 |
| P6 分发 | 安装/卸载、右键注册、更新 | 干净 Windows 机器可安装并右键使用 |

P1 已完成：Go 原生工作台、拖拽/选择文件与文件夹、4 格式快速转换、逐文件缩略图与体积变化、取消与重试、输出策略记忆、发送到脚本。

P2 已完成：缩放（按宽/高/百分比/自定义框，含 cover/contain/fill/inside）、智能去边（容差与修剪方向）、手动裁剪（四边像素）。三者共用队列、进度、取消与结果卡片；缩放和裁剪在运行前于队列行内预览目标尺寸。参数变化只清除该操作的结果，切页保留其他操作的结果。

P2 与旧版的差异（有意为之）：去边检测不到可去边缘时跳过并说明，而不是复制一张原图；自定义缩放选 contain 时补透明而不是白底；GIF/BMP/TIFF 选择「保持原格式」时输出 PNG；裁剪要求至少一个方向大于 0。

P3 已完成：「构图」页含智能居中与画布扩边两个模式，二者共用去边探测的主体包围盒。居中保持画布尺寸，按「四周 / 仅上下 / 仅左右」重新分配留白，未参与的轴保持主体原位置；已居中或画面无可调整留白时跳过。扩边按比例（16:9、9:16、1:1、4:5、自定义）与长边新建画布，主体等比缩放到「主体占比」并居中，宽度超过画布 95% 时自动改为按宽限高；填充可选背景色、透明、白、黑。产物后缀 `_centered` / `_pad`，扩边在队列行内预览目标画布尺寸。

P4 已完成：「切图」页是单图编辑器，图片按队列选择，画布显示缩放后的预览（长边最多 2048 px，切分线仍按原图像素保存）。竖线/横线/平移三种模式，点击加线、Alt 反向、拖动移动（不越过相邻线）、双击删除、吸附到相邻线；滚轮以指针为中心缩放，空格/中键/Shift 拖动平移。等分行列即时生成切割线，切割线严格递增且总数不超过 500。每片可选「每片居中」复用构图页的居中算法。切割写入以原图命名的新文件夹，切片名 `_rNN_cNN`，取消会删除未完成的文件夹。

P4 与旧版的差异（有意为之）：编辑器只处理队列中当前选中的一张图（旧 Web UI 也是单图），不再导出 `split_config.json` 与调试网格；每片居中的填充复用统一填充选项。

P5 已完成：「抠图」页使用本地 ONNX 推理，完全离线。模型分快速（U2-Netp，~4.5 MB）与精细（U2-Net，~168 MB）两档，默认精细；一个批次只启动一个 worker，模型加载一次后逐张处理。边缘羽化 0–3 px 只作用于 alpha。输出保留直通 alpha，源为 PNG/WebP/AVIF 时保持原格式，JPEG 回落 PNG 并说明。产物后缀 `_nobg`，子目录默认 `matting`。worker 为独立进程（Rust + ONNX Runtime）；崩溃只影响当前批次，取消即终止进程，下一批重新启动。

P5 与旧版的差异（有意为之）：不再依赖 Node 与 AGPL 的 `@imgly/background-removal-node`；模型授权与分发策略见 [`docs/adr/0008-matting-worker.md`](../adr/0008-matting-worker.md)。质量基线以样张人工验收为准，不追求与旧模型逐像素一致。

P6 已完成：`go tool mygo build` 产出按用户安装的 NSIS 安装包 `smartimage-setup-<版本>-amd64.exe`，安装到 `%LOCALAPPDATA%\Programs\SmartImage`，无需管理员；开始菜单快捷方式、卸载项与图片「打开方式」由安装器注册，安装器钩子另外写入两项右键菜单（「用 SmartImage 打开」「转成 WebP」），卸载时清理。worker、两档模型与 VC++ 运行库随包分发，缺失运行库时安装器静默安装。升级方式是运行新版本安装器；卸载保留 `%APPDATA%\SmartImage` 的设置。分发决策见 [`docs/adr/0009-windows-distribution.md`](../adr/0009-windows-distribution.md)。

P6 与旧版的差异（有意为之）：不再依赖 Node 与便携包；右键入口改为安装器注册的经典菜单项（Windows 11 在「显示更多选项」中），不注册级联 COM 菜单；暂未配置代码签名，对外分发前需补证书与 SmartScreen 信誉。

## 七、已确认的决策

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 右键入口 | B + 少量 A：一键「转成 WebP」+「打开工具并导入」 |
| 2 | 主窗口结构 | 左侧工具导航 + 文件队列 + 参数工具栏；按最佳交互实践迭代 |
| 3 | 输出策略 | 采用 4.4 的统一新规则，不复制旧版后缀混用 |
| 4 | 切图优先级 | 按 P1→P4 顺序 |
| 5 | AI 抠图 | 放到 P4 之后再做 |
